1. System Overview

1.1 Project Background

The Carbon Platform is a comprehensive system designed for electric vehicle charging facility management and carbon credit trading. With the increasing global focus on environmental protection and the growing adoption of electric vehicles, effectively managing charging facilities and quantifying the benefits of carbon emission reduction has become a critical technical challenge.

1.2 System Objectives

  • Provide complete charging facility management solutions
  • Implement digital management of carbon credit trading
  • Support unified management of multiple vendors and devices
  • Provide real-time monitoring and data analysis capabilities
  • Ensure data security and system stability

1.3 Business Value

Core Value Propositions

  • Environmental Benefits: Promote green energy development and reduce carbon emissions
  • Economic Benefits: Support carbon credit trading and create economic value
  • Management Benefits: Improve charging facility management efficiency
  • Social Benefits: Drive sustainable development goals

2. System Architecture

2.1 Overall Architecture

The system adopts a modern three-tier architecture design, including frontend presentation layer, backend business layer, and data persistence layer. The overall architecture features high availability, scalability, and security.

Frontend Layer (Presentation Layer)

  • Thymeleaf Template Engine
  • Bootstrap 4 Responsive Framework
  • JavaScript Dynamic Interaction
  • Internationalization Support

Backend Layer (Business Layer)

  • Spring Boot 2.6.15
  • Spring Security Framework
  • JPA/Hibernate Data Access
  • JWT Token Authentication

Data Layer (Data Layer)

  • MySQL 8.0 Database
  • Azure Cloud Deployment
  • Data Backup and Recovery
  • Performance Monitoring

4. Core Modules

4.1 User Management Module

Provides complete user registration, login, and permission management functionality. Supports Role-Based Access Control (RBAC), including administrator and regular user roles.

Main Features:

  • User registration and login
  • JWT Token authentication
  • Role-based permission management
  • Password encrypted storage

4.2 Charging Station Management Module

Complete charging station information management system, supporting GPS positioning, status monitoring, power load management, providing intuitive map interface to display charging station distribution.

Data Fields:

  • Charging Station ID (Primary Key)
  • Vendor ID
  • Charging Station Name
  • GPS Coordinates (Latitude/Longitude)
  • Charging Station Power
  • City and Address Information
  • Energy Storage Enable Status
  • Power Source

4.3 Charging Pile Management Module

Detailed charging pile device management, including device type, power specifications, brand information, supporting composite primary key design to ensure data integrity.

Composite Primary Key Design:

  • Charging Pile ID + Connection ID
  • Associated Charging Station ID
  • Vendor ID
  • Device Type and Brand
  • Power Specifications (kW/A/V)
  • Device Status

4.4 Charging Record Module

Complete charging transaction record system, recording charging time, power consumption, vehicle information, supporting carbon credit marking, providing data foundation for carbon credit trading.

Transaction Record Fields:

  • Transaction Number (Primary Key)
  • Vendor ID, Charging Station ID, Charging Pile ID
  • Start Time and End Time
  • Charging Amount (kWh)
  • Vehicle Information (Vehicle Type, Tonnage, License Plate)
  • Carbon Credit Marking (Y/N)
  • Invoice Information

5. Security Mechanisms

5.1 Authentication Mechanism

JWT Token Authentication

  • Stateless Authentication: Stateless authentication mechanism based on JSON Web Token
  • Token Validity Period: 12 hours (43200 seconds)
  • Auto Refresh: Supports automatic token refresh mechanism
  • Password Encryption: Uses BCrypt encryption algorithm

5.2 Authorization Control

  • Role-Based Access Control (RBAC):
    • ROLE_ADMIN: System administrator permissions
    • ROLE_USER: Regular user permissions
  • Resource Access Control: Users can only access their own data
  • API Permission Control: Annotation-based control using Spring Security

5.3 Data Security

  • SQL Injection Protection: Uses JPA parameterized queries
  • XSS Protection: Input validation and output encoding
  • CSRF Protection: Spring Security CSRF protection
  • Sensitive Data Encryption: Encrypted storage of sensitive information like passwords
